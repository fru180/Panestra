### 2.1 設計原則

- セッションごとに1個のPTYとプロセスグループを起動する。
- 全ペインで1個のWebGPU rendererとCanvasを共有する。
- DOM UI、GPU描画、PTY、Git、MCP、エージェントイベント処理を分離する。
- Rust側でANSIを解析し、ブラウザへターミナル状態の差分を送る。
- バイナリ解析とセルバッファ更新はWeb Workerで行う。
- WebSocketは1接続とし、有限サイズのapplication messageへ分割してセッションIDで多重化する。
- すべてのキュー、履歴、フレーム、入力に上限を設ける。
- あるセッションの負荷や障害によって、他セッションの制御と入力を枯渇させない。

### 2.2 技術選定

| 領域 | 初期版の選定 |
|---|---|
| 常駐デーモン | Rust |
| 非同期ランタイム | Tokio |
| HTTP / WebSocket | axum |
| 対応OS | macOS |
| PTY | `portable-pty`を第一候補とし、不足機能をmacOS adapterで補う |
| ターミナル状態 | `alacritty_terminal`を第一候補として事前検証する |
| フロントエンド | TypeScript / SolidJS |
| ターミナル描画 | 独自WebGPU renderer |
| バイナリ解析 | Web Worker |
| 永続メタデータ | SQLite |
| スクロールバック | 有限メモリバッファと圧縮ディスクチャンク |
| Git情報 | shellを介さず引数配列で起動する`git`コマンド |
| ログと計測 | `tracing`と機密情報を除外したmetrics |
| テスト | Rust unit / integration、Playwright、fuzz、負荷計測 |

PTYライブラリ、ターミナル状態ライブラリ、WebGPU rendererは、日本語、結合文字、alternate screen、mouse mode、動的PTY Resize、スナップショット生成を実装着手時に検証する。必要機能を満たさない候補は公開APIへ組み込む前に交換する。

初期版はmacOSだけを対応対象とする。LinuxとWindowsのPTY、signal、プロセス包含、パス、ファイル権限の差異は初期版へ含めない。

## 3. セッション管理

### 3.1 セッション作成

セッションは構造化された起動要求から作成する。

```ts
type CreateSessionRequest = {
  name: string;
  projectId?: string;
  command: string;
  args: string[];
  cwd: string;
  env?: Record<string, string>;
  agentIntegration?: "codex" | "claude";
  cols?: number;
  rows?: number;
};
```

- `command`と`args`をシェル文字列として連結または再解釈しない。
- shell展開が必要な場合は、ユーザーがshell自体を`command`として明示する。
- `cwd`の存在、ディレクトリ種別、アクセス権を起動前に検証する。
- `cols`と`rows`はHTTP API互換性のため任意指定を残し、許可範囲内で検証する。Web UIは選択中の表示サイズから初期値を自動算出し、入力欄を設けない。APIで省略した場合は80×24を使用する。
- 明示的な環境変数の値は永続化しない。
- 保存済み起動テンプレートには環境変数名を保存できるが、秘密値を保存しない。
- `agentIntegration`が指定された場合は、対応する公式起動フローを使用し、対象バージョンと公式イベント連携の対応可否を確認する。
- 初期版のCodexとClaude Codeは、通常のCLI TUIをPTY内で実行し、各providerの公式lifecycle hookから状態を取得する。Codex App Serverを状態取得経路として使用しない。
- adapterはproviderごとに検証済みの方法でhook設定を与える。providerがhookのtrust確認を要求する場合は、初回セットアップでユーザーの明示承認を得る。trust確認を無効化または迂回しない。
- Panestraの状態連携設定をproject設定へ自動保存せず、Panestra外で起動したCLIへ状態連携を強制しない。
- `agentIntegration`が指定された場合は、そのセッションに束縛されたPanestra MCP接続情報もエージェント設定へ注入する。
- 対応外バージョンで`agentIntegration`を要求した起動は拒否する。通常のターミナルセッションの作成と、その中での手動実行は制限しない。
- `agentIntegration`がないセッションでは、起動時および実行中のコマンドからエージェントを自動検出せず、MCP接続情報も注入しない。

### 3.2 プロセスグループ

- セッションごとに独立したPTYとプロセスグループを作成する。
- 終了操作はPTYランチャーを起点とする管理対象プロセスツリー全体を対象とし、対話シェルやjob controlが別PGIDを作成した場合も追跡する。
- 画面上の削除操作は1回の確認後、プロセスグループへ通常終了シグナルを送り、2.5秒の猶予後もグループが残る場合は自動的に強制終了する。この確認は必要時の強制終了も承認する。
- 削除完了は親プロセスの終了だけで判定せず、PID再利用を識別したうえで管理対象プロセスツリーが消滅したことを確認してから画面へ返す。
- デーモンはセッションランチャーとの監視パイプを保持する。
- ランチャーは監視パイプの切断を検知したら配下のプロセスグループを終了し、自身も終了する。
- ランチャーをデーモン再起動後のPTY再接続には使用しない。
- PTY配下のプロセスが二重forkなどで意図的にreparentされ、管理対象プロセスツリーから離脱した場合、そのプロセスの終了は保証しない。

### 3.3 ブラウザ再接続

- ブラウザを閉じても、同じデーモンが動作している限りPTYを継続する。
- 再接続時はセッション一覧と表示対象セッションのFullSnapshotを取得する。
- 過去履歴は必要になった時点でページ単位に取得する。
- 再接続前のブラウザが持つ未送信入力を再送しない。
- 同じタブの再読み込みでは、同一originの`sessionStorage`に保持したbrowser session credentialを使って再認証する。
- タブを閉じてcredentialを失った場合は、Panestraのランチャーまたは`open`操作から新しい1回限りのbootstrap tokenを発行して同じデーモンへ再接続する。

### 3.4 デーモン終了

- 正常終了、異常終了を問わず、デーモン終了時は全セッションを終了扱いとする。
- 監視パイプとmacOSで利用可能なプロセス管理機構により、Panestraが管理するPTYとプロセスグループを終了させる。
- 次回起動時に既存PIDやPTYへ再接続しない。
- SQLiteに実行中と記録されたセッションは、次回起動時に`daemon_terminated`として終了確定する。
- 最後に確定したactive screen checkpoint、確定済みscrollback、終了理由、プロジェクトは再起動後も閲覧できる。
- 異常終了直前の未checkpoint画面と未確定scrollbackの保存は保証しない。

### 3.5 セッション削除

- 実行中セッションは削除できない。先に終了または強制終了する。
- メタデータだけを削除するか、履歴を含めて削除するか選択できる。
- 履歴を含む削除は確認を必要とし、復元できないことを表示する。

## 4. 状態モデルとエージェント連携

### 4.1 状態の分離

```ts
type ProcessState =
  | "starting"
  | "running"
  | "exited"
  | "killed";

type ConnectionState =
  | "connecting"
  | "connected"
  | "resyncing"
  | "disconnected";

type AgentState =
  | "initializing"
  | "working"
  | "waiting_approval"
  | "awaiting_user"
  | "integration_error";

type AttentionState =
  | "none"
  | "agent_awaiting_user"
  | "needs_approval"
  | "agent_integration_error"
  | "process_exited";
```

- `ProcessState`はPTYプロセスの事実だけを表す。
- `ConnectionState`はブラウザ接続ごとに保持し、Sessionへ永続化しない。
- `AgentState`は公式イベントから正規化した最新状態を表す。
- `agentIntegration`がないセッションは`AgentState`を持たない。
- `AttentionState`は通知、強調、絞り込みに使う派生状態とする。
- `awaiting_user`は公式イベントがエージェントのターン終了を示し、ユーザー入力を受けられる状態だけを表す。返答が質問を含むか、タスクが完了または失敗したか、成果物が正しいかは表さない。
- `AgentState`が`awaiting_user`でも、PTYプロセスが継続していれば`ProcessState`は`running`となる。

### 4.2 対象アダプター

- Codex Adapter
- Claude Code Adapter

初期版で状態連携付き起動を許可する動作確認範囲は、Codex CLI `0.144.x`、Claude Code `2.1.211`以上`2.2.0`未満とする。範囲外のバージョンは通常のターミナル内で手動起動できるが、状態連携付き起動は拒否する。

各adapterは、リリースで明示した対応バージョンについて次を提供する。

- 公式イベント連携の初期化と能力確認
- セッション専用Panestra MCP設定の注入
- 新しい行動の開始後に`panestra.report_action_start`を呼び出すよう求める起動指示
- 連携準備中、作業中、承認待ち、ユーザー応答待ちの正規化
- providerのsession ID、turn ID、event IDを利用した対応付け。公式IDがないeventにはadapter内の受信順序を付与する
- hook設定、初期handshake、event payloadの異常検出
- 利用可能な場合のコンテキスト利用量、コスト、変更量などの付加情報

付加情報とMCPによる行動情報は取得できない場合に省略できるが、基本の`AgentState`は対応済みの条件として必須とする。

初期版の状態変換は次に固定する。provider固有の返答内容を解析して状態を追加しない。

| AgentState | Codex公式hook | Claude Code公式hook | Panestra側の事実 |
|---|---|---|---|
| `initializing` | hook初期化完了前 | hook初期化完了前 | adapter起動からSessionStart受理まで |
| `working` | `UserPromptSubmit` | `UserPromptSubmit` | 承認待ち中にPTY入力を受け取った場合は、既知の待ち状態に対するユーザー応答として`working`へ戻す |
| `waiting_approval` | `PermissionRequest` | `PermissionRequest` | なし |
| `awaiting_user` | `Stop` | `Stop` | なし |
| `integration_error` | hook設定、初期handshake、event検証の失敗 | hook設定、初期handshake、event検証の失敗 | なし |

`Stop`はエージェントの返答が止まったことだけを意味する。`TaskCompleted`、返答本文、terminal出力を使ってタスク成果の成功または失敗を判定しない。承認待ちからのPTY入力による`working`への遷移は、既知の待ち状態にユーザーが応答した事実だけを表し、承認または拒否の結果は判定しない。

### 4.3 許可する情報源

優先順位:

1. 公式の構造化イベントストリームまたはAPI
2. 公式hookまたはplugin API
3. 公式仕様に記載された構造化ログ

禁止する手法:

- ターミナル画面に表示された文言のパターンマッチ
- ANSI出力の見た目からの状態推測
- prompt記号や色からの入力待ち推測
- 非公開ファイル形式への依存

### 4.4 連携障害

- 公式hookの設定、初期handshakeまたはevent検証に失敗した場合は`integration_error`へ移行する。
- 連携障害が起きてもPTY、入力、画面描画を継続する。
- adapter再初期化後は、公式の新しいイベントを取得してから正常状態へ戻す。
- adapterの異常や不正イベントを他セッションへ波及させない。

### 4.5 Panestra MCP

Panestra daemonは、状態連携付きで起動したエージェントに対してセッション専用MCP serverとして動作する。MCP接続のcredentialへセッションを束縛し、tool inputから`sessionId`を指定させない。

初期版は行動開始を申告する`panestra.report_action_start`を提供する。

MCP toolの呼び出しはモデル判断である。adapterは行動開始後の呼び出しをエージェントへ求めるが、すべての行動での呼び出し、行動開始との同時性、申告内容の完全性を保証しない。MCP申告はエージェント状態とは独立したbest effortの付加情報として扱う。

```ts
type ReportActionStartInputV1 = {
  schemaVersion: 1;
  taskSummary: string;
  repositoryPath: string;
  gitBranch?: string;
};

type ReportActionStartResultV1 = {
  actionId: string;
  acceptedAt: string;
  repositoryPath: string;
};
```

- `taskSummary`は改行を含まない簡潔な一文とし、入力サイズに上限を設ける。
- `repositoryPath`は必須とし、Gitの使用有無にかかわらず作業対象のローカルディレクトリを指定する。
- `gitBranch`は任意の自己申告情報とし、Gitコマンドで検証または上書きしない。
- `repositoryPath`はcanonicalizeし、存在、ディレクトリ種別、アクセス権を検証する。
- 行動開始申告を受理したら新しい`actionId`を発行し、同じセッションの前回申告を履歴へ移す。
- 現在の`AgentState`が`awaiting_user`の場合、最新申告を現在の作業ではなく「直前の行動」として表示する。
- toolが呼ばれない場合は、既存の行動情報を新しい行動の情報として流用せず「未取得」と表示する。
- MCP申告の失敗は`AgentState`を変更せず、行動情報を「未取得」と表示する。
- MCP切断後も公式イベント連携とターミナル操作を継続する。
- payloadを`schemaVersion`ごとに永続化する。同じversionには後方互換な任意フィールドだけを追加し、必須項目や意味を変更する場合は新versionを定義する。

## 5. プロジェクトとGit

### 5.1 Project

```ts
type Project = {
  id: string;
  name: string;
  rootPath: string;
  color?: string;
  tags: string[];
  repositoryUrl?: string;
  createdAt: string;
  updatedAt: string;
};
```

### 5.2 shellの現在ディレクトリ

- `launchCwd`はセッション作成時の固定値とする。
- `currentCwd`はshellがOSC 7などの明示的なshell integrationを送信した場合だけ更新する。
- ターミナル画面やpromptから現在ディレクトリを推測しない。
- shell integrationがない場合は`launchCwd`を表示し、現在位置を追跡していないことを示す。
- `launchCwd`と`currentCwd`を、エージェントが申告した`repositoryPath`の代用にしない。

### 5.3 行動情報とGit情報

- タスク概要
- 申告された作業リポジトリのディレクトリ名とパス
- 申告されたGitブランチ
- staged、unstaged、untracked状態
- 変更ファイル数、追加行数、削除行数
- upstreamがある場合のahead、behind
- コンフリクト状態

`repositoryPath`がGit管理下かどうかを判定する。Git管理下の場合は指定パスからworking tree rootを解決し、そのworking treeを基点としてGit状態を取得する。通常checkoutと追加worktreeを区別しない。Git管理外の場合はディレクトリ情報だけを表示し、Git状態を表示しない。

`gitBranch`はエージェントの任意申告値をそのまま表示する。Git状態取得時に得られる実際のブランチ名で、申告値を検証または上書きしない。

Git取得処理は描画経路から分離し、次を満たす。

- canonicalなworking tree rootごとに結果を共有する。
- 同じworking treeへの重複実行をまとめ、別worktreeの状態を混在させない。
- 実行時間と同時実行数に上限を持つ。
- 前回処理が完了していない場合は同じ処理を重ねない。
- 巨大リポジトリ、submodule、Gitロック、削除済みworktreeを当該処理のエラーとして隔離する。
- Gitコマンドへユーザー文字列をshell展開して渡さない。
- 変更数をエージェント固有の変更量として扱わない。

## 6. UIとターミナル操作

### 6.1 画面構成

- 小、中、大のターミナル表示サイズ
- ブラウザ幅に応じたペインの自動折り返し
- ペイン領域内の縦横スクロール
- 特定ペインの拡大
- プロジェクトと注意要求による絞り込み

各ペインは表示サイズごとの固定実寸で配置し、PTYの現在の論理列数・行数から物理寸法を決めない。横方向へ収まる数だけ配置してから次の行へ折り返す。1ペイン分の幅に満たない場合は1列とし、ペイン領域内で横スクロールする。上部ツールバーと左サイドバーはスクロールさせない。

各ペインヘッダーとサイドバーにはターミナル削除操作を表示する。削除中は重複操作を無効化し、デーモンが管理対象プロセスグループの終了を確認した後にペインを除去する。削除操作ではSQLite上のセッション記録、checkpoint、履歴を保持する。

- 文字セル: 全表示サイズで6×12px
- 小: 本文384×230.4px、通常64列×19行
- 中: 本文540×324px、通常90列×27行。初期値とする。
- 大: 本文720×432px、通常120列×36行
- ヘッダー: 全表示サイズで44px

選択した表示サイズはブラウザのlocal storageへ保存し、値がない場合または不正な場合は中を使用する。

一覧のペインは表示サイズにかかわらず選択してアクティブ化し、その場で操作できる。拡大表示は精読と長時間操作のための任意機能とし、操作開始の条件にしない。

`ProcessState`が`exited`または`killed`へ変わったセッションは、SessionState受信時にターミナル一覧、ペイン領域、購読対象から除外する。SQLite上のセッション記録、確定済みcheckpoint、履歴は保存設定に従って保持し、終了したターミナルを通常画面へ残す目的には使用しない。

### 6.2 ペインヘッダー

表示優先度の高い順に次を表示し、狭いペインでは低優先度項目を詳細パネルへ移す。

- 注意要求
- エージェント状態。状態連携がない場合はターミナル表記
- 現在または直前のタスク概要
- セッション名
- プロジェクト名
- 作業リポジトリ名
- 申告された場合のGitブランチ
- プロセス状態
- 最終活動時刻
- shellの現在ディレクトリまたは起動ディレクトリ
- Git管理下の場合のworking tree全体の変更ファイル数
- エージェントイベントの情報源と連携状態

### 6.3 入力

- 同時に入力を受け取るアクティブペインは1つだけとする。
- 一覧内のペインを選択すると、表示サイズと配置を変えずにアクティブ化する。
- ペインを拡大した場合は自動的にアクティブ化する。
- アクティブペインは拡大表示の有無にかかわらず同じ入力機能を提供する。
- 通常文字、制御キー、日本語IME、コピー、貼り付けを扱う。
- bracketed paste、application cursor/keypad mode、focus in/outを扱う。
- terminal mouse reportingと通常の範囲選択を切り替える。
- 入力イベントには接続内で単調増加する`inputSequence`を付け、重複適用を防ぐ。

### 6.4 DOM補助層

ターミナル本体はCanvasへ描画し、次はDOMで実現する。

- IME compositionを受け取る非表示textarea
- コピー対象を生成する選択モデル
- ペインヘッダー、メニュー、通知
- アクティブ画面を行単位で公開する読み取り専用DOMミラー
- キーボード操作可能なフォーカス管理

DOMミラーは高頻度出力を自動読み上げせず、ユーザーが要求したときに現在画面を読み取れるようにする。

## 7. 対応ブラウザとWebGPU

### 7.1 対応判定

リリースごとに動作確認済みのデスクトップブラウザと最低バージョンを明記する。起動時に次の機能を検査する。

初期版の対応ブラウザはmacOS版Google Chrome 121以降とMicrosoft Edge 121以降とする。同じ機能を持つ場合でも、動作確認対象に含まれないブラウザは起動不可とする。

- WebGPU
- Web Worker
- WebSocket binary frame
- `TextDecoder`
- Clipboard APIまたは許可された同等機能
- IME composition event
- 通知を有効にする場合のNotification API

WebGPU adapterとdeviceを取得できない場合は起動しない。非対応時はPTYを自動作成せず、理由と対応環境を表示する。Canvas 2DまたはWebGLへフォールバックしない。

### 7.2 device lost

- device lostを検出したら入力を一時停止し、復旧中であることを表示する。
- renderer、Canvas、グリフアトラスを再作成する。
- 表示対象セッションのFullSnapshotを再適用する。
- 復旧できない場合もPTYを継続し、ブラウザ再読み込みを案内する。

## 8. ターミナル描画

### 8.1 対応文字

初期版はASCII、日本語、全角文字、結合文字、罫線、一般記号、Nerd FontsのPrivate Use Area、基本的なセルスタイルへ対応する。

絵文字、ZWJ絵文字シーケンス、kitty、sixel、iTerm2などの画像プロトコルには対応せず、対象外文字を置換グリフとして表示する。文字幅はデーモンとブラウザで同じUnicode幅テーブルの版を使用する。

### 8.2 セルモデル

```rust
struct Cell {
    grapheme_id: u32,
    style_id: u32,
    width: u8,       // 0: 継続セル, 1: 半角, 2: 全角
    flags: u16,
}

struct GraphemeRecord {
    id: u32,
    utf8: Vec<u8>,
}

struct StyleRecord {
    id: u32,
    foreground: u32,
    background: u32,
    underline_color: u32,
    attributes: u32,
}
```

- graphemeはUnicode grapheme cluster単位で管理する。
- 全角文字の後続セルは`width = 0`とする。
- graphemeとstyleの辞書は接続単位で定義する。
- 未定義IDを含む差分を適用しない。
- 色は既定色、indexed color、true colorを区別する。
- attributesはbold、dim、italic、underline style、inverse、hidden、strikethrough、blinkを表す。
- OSC 8 hyperlinkはセルとは別の範囲メタデータとして扱う。

### 8.3 グリフアトラス

- 通常文字はSemiboldの等幅フォントで描画する。
- アトラスのセルは表示セルと同じ縦横比を保ち、2倍解像度で生成して横圧縮と拡大時のぼけを避ける。
- ASCIIと頻出記号を起動時に準備する。
- 日本語、結合文字、Nerd Fontsは必要時に動的追加する。
- アトラスへ上限を設定し、未使用グリフを再生成可能な形で退避する。
- フォント、DPI、device変更時はアトラスを再構築する。

### 8.4 描画更新

- 変更がないペインを再描画しない。
- アクティブペイン、注意要求、最近変更されたペインの順に優先する。
- 非表示ペインを描画しない。
- 描画頻度はdirty stateとanimation frameに基づいて決める。
- FPSを初期版の完了判定に使用しない。

## 9. PTY論理サイズ

- ペイン本文の幅を6px、高さを12pxで割り、端数を切り捨てて論理列数と行数を算出する。
- 列数は40〜300、行数は12〜120へ制限する。
- 小、中、大の変更と拡大・縮小でPTY Resizeを送信する。拡大中はResizeObserver由来の変更を75msでdebounceし、同一列数・行数への重複送信を行わない。
- 一覧でのブラウザ幅変更はペインの並びだけを変え、固定されたペイン本文寸法とPTY論理サイズを変えない。
- PTY master、active/alternate screen、セッションメタデータ、SQLite上の現在寸法を一体で更新し、sequence numberを進める。
- resize後は`SessionState`と強制FullSnapshotを送信し、旧寸法の差分を新寸法へ適用しない。
- `vt100`は既に表示済みの通常出力を再折り返ししない。resize後の出力、shell line editor、`SIGWINCH`へ応答するTUIは新しい寸法へ追従する。
- Resize権を持たない接続は共有PTYを変更せず、現在の論理画面全体がペインへ収まらない場合だけ等比縮小する。
- 論理画面はペイン本文の左上を基準にし、端数の余白は右側と下側へ背景色で表示する。
- マウスイベントを表示座標から論理セル座標へ変換し、余白上のイベントをPTYへ送信しない。

## 10. 通信プロトコル

### 10.1 基本方針

- 1本のBinary WebSocketを使用する。
- 高頻度経路にJSONとBase64を使用しない。
- セッションIDで多重化する。
- 制御メッセージと画面データに優先度を持たせる。
- すべてのapplication messageを有限サイズに制限し、大きな画面データは複数messageへ分割する。
- プロトコル版、最大application messageサイズ、byte orderを明示する。
- 不明な必須メッセージまたは互換性のない版を受信した場合は接続を終了する。

### 10.2 共通エンベロープ

```text
Application Message Envelope
├─ magic
├─ protocol_version
├─ message_type
├─ flags
├─ payload_length
└─ payload
```

- 複数byte整数はnetwork byte orderとする。
- `payload_length`を受信前に上限検証する。
- 圧縮はメッセージ単位とし、展開後サイズにも上限を設ける。

### 10.3 メッセージ種別

```text
Hello / HelloAck
SessionList
Subscribe / Unsubscribe
GraphemeDefine
StyleDefine
ScreenDiff
FullSnapshotBegin / FullSnapshotChunk / FullSnapshotEnd
Input
CursorAndModeUpdate
SessionState
AgentState
ActionContext
SessionExit
ResyncRequest
SnapshotAck
InputLeaseRequest / InputLeaseState
ResizeLeaseRequest / ResizeLeaseState
Resize
HistoryRequest / HistoryChunk
Heartbeat
ProtocolError
```

`Resize`はResize権を持つ接続だけが送信できる。列数・行数・本文pixel寸法を含め、終了済みセッション、未購読セッション、許可範囲外、重複寸法の要求を拒否または無視する。

### 10.4 画面世代と差分

各セッションは、デーモン起動ごとの`daemonEpoch`、セッション生成時の`sessionGeneration`、スナップショットごとの`snapshotEpoch`を持つ。

```text
ScreenDiff
├─ session_id
├─ daemon_epoch
├─ session_generation
├─ snapshot_epoch
├─ sequence_number
├─ cursor_and_modes
└─ changed_regions[]
```

- `sequence_number`はセッションごと、スナップショットごとに単調増加する。
- ブラウザは異なる世代の差分を適用しない。
- 未定義graphemeまたはstyleを参照する差分を適用しない。
- `ScreenDiff`が上限を超える場合は、changed regionを複数の独立したmessageへ分割する。
- `FullSnapshotBegin`から`FullSnapshotEnd`までを1つの論理snapshotとし、各chunkを独立したWebSocket messageとして送る。
- snapshot chunk間には制御、入力、他セッションのmessageを送信できる。
- FullSnapshot適用中に届いた古い差分を破棄する。
- `FullSnapshotEnd`の適用後に`SnapshotAck`を返す。

シーケンス番号は、WebSocket内のパケット欠落検出ではなく、差分統合、破棄、再接続、世代不一致の検出に使用する。

### 10.5 公平制御とバックプレッシャー

- セッションごとに独立した有限の差分キューを持つ。
- 接続全体にも送信待ち上限を持つ。
- 制御、認証、入力lease、終了、注意要求を画面差分より優先する。
- 画面差分内ではアクティブペインを優先し、他ペインを公平に巡回する。
- 同一セッションの未送信差分を可能な限り結合する。
- schedulerは有限サイズのapplication messageを1単位として選択し、論理snapshotの全chunkを連続送信しない。
- キュー上限を超えたセッションでは中間差分を破棄し、最新状態からchunk化したFullSnapshotを生成する。
- あるセッションのキュー超過で他セッションのキューを消費しない。
- 単一接続であるため通信路自体の停止は全セッションへ影響するが、アプリケーション内の送信待ちによるstarvationは防止する。
- Web Worker内の適用待ち量をデーモンへ通知できるようにする。
- 不正フレームと上限超過を接続またはセッション単位で処理する。

## 11. スクロールバックと永続化

### 11.1 保存構造

```text
Active Screen
  → 現在のPTY寸法に対応するセルグリッド

Active Screen Checkpoint
  → 最後に確定したセルグリッドの永続snapshot

Recent Scrollback
  → 行、grapheme、style runの有限メモリバッファ

Old Scrollback
  → 圧縮されたディスクチャンク
```

- セッションごとに最大保持量を設定できる。
- メモリとディスクの両方に上限を持つ。
- 古い履歴を自動削除できる。
- 履歴保存をセッションごとに無効化できる。
- テキスト検索とエクスポートに対応する。
- ANSI由来のスタイルを保持する。
- alternate screenを通常scrollbackと区別する。
- 再接続時に全履歴を読み込まない。
- 履歴保存が有効なセッションではactive screenを定期的、および正常なセッション終了時とデーモン終了時にcheckpointする。
- checkpointは一時ファイルへ完全に書き出してからatomicに確定し、途中書き込みを復元対象にしない。
- 異常終了後は最後に確定したcheckpointだけを復元し、それ以降のactive screenを復元したと表示しない。
- チャンク途中でデーモンが終了しても、確定済みチャンクを読み取れる。
- 検索、取得、エクスポートに結果件数と出力サイズの上限を設ける。

### 11.2 Session

```ts
type Session = {
  id: string;
  projectId?: string;
  name: string;
  command: string;
  args: string[];
  launchCwd: string;
  currentCwd?: string;
  agentIntegration?: "codex" | "claude";
  currentActionId?: string;
  processState: ProcessState;
  pid?: number;
  processGroupId?: number;
  cols: number;
  rows: number;
  daemonEpoch: string;
  sessionGeneration: string;
  createdAt: string;
  lastActivityAt?: string;
  lastCheckpointAt?: string;
  exitedAt?: string;
  exitCode?: number;
  exitReason?:
    | "normal"
    | "signal"
    | "forced"
    | "daemon_terminated"
    | "launch_failed";
};
```

### 11.3 ActionContext

```ts
type ActionContextV1 = {
  id: string;
  schemaVersion: 1;
  sessionId: string;
  taskSummary: string;
  repositoryPath: string;
  gitBranch?: string;
  gitWorkingTreeRoot?: string;
  acceptedAt: string;
};
```

- `repositoryPath`には申告値をcanonicalizeしたディレクトリパスを保存する。
- `gitWorkingTreeRoot`はGit管理下の場合だけPanestraが解決して保存する。
- `gitBranch`はエージェントの申告値であり、Panestraの実測値ではない。
- 新しい行動を受理したら`Session.currentActionId`を更新し、以前のActionContextは履歴として保持する。

### 11.4 永続化規則

- SQLiteはメタデータ、状態、ActionContext履歴、active screen checkpoint索引、履歴チャンク索引を保存する。
- active screen checkpointとターミナル履歴本体は、atomicに確定できる個別ファイルへ保存する。
- 接続状態、入力lease、Resize権、未送信差分キューを永続化しない。
- PIDをデーモン再起動後の再接続判断に使用しない。
- 環境変数値、bootstrap token、browser session credential、WebSocket ticketをSQLiteへ保存しない。
- スキーマにmigration versionを持たせる。

## 12. 複数接続と入力権・Resize権

初期版は単一ユーザー向けだが、再読み込みと複数タブによる複数接続を安全に扱う。

- 複数接続から同じセッションを閲覧できる。
- 入力できる接続はセッションごとに1つだけとする。
- 入力権はデーモンが発行するleaseとして管理する。
- 明示的な取得操作で入力権を移動できる。
- leaseを持たない接続からの入力を拒否する。
- 接続切断時にleaseを失効させる。
- PTYは同時に1つの論理サイズしか持てないため、セッションごとに1接続だけへResize権を付与する。
- 最初にセッションを表示した接続が非強制でResize権を取得する。所有接続の切断時は解放し、表示中の別接続が再取得できる。
- 別接続が入力権を強制取得した場合は、Resize権も同じ接続へ移す。
- Resize権の取得、移動、解放を購読中の全接続へ通知する。
- Resize権を持たない接続は共有PTYの寸法を変更しない。
- スクロール位置、選択範囲、拡大表示を接続間で共有しない。

## 14. セキュリティ

### 14.1 脅威モデル

本製品はログイン中のOSユーザーと同等の権限でローカルコマンドを実行できる。悪意あるWebページからのlocalhostアクセス、token漏えい、保存履歴からの秘密情報漏えい、不正なANSIまたは巨大入力による資源枯渇を主な脅威とする。

### 14.2 接続保護

- TCPは明示的なloopbackアドレスだけで待ち受ける。
- HTTPとWebSocketを含む全APIを認証する。
- 起動ごとに十分な強度のtokenを生成する。
- bootstrap tokenとbrowser session credentialをURL query、cookie、localStorage、ログへ保存しない。
- browser session credentialは完全一致したoriginの`sessionStorage`だけに保持し、HTTPのAuthorization headerへ付与する。
- tokenファイルはOS所有者だけが読める権限にする。
- WebSocket upgrade時にHost、Origin、1回限りのWebSocket ticketを検証する。
- 許可Originを完全一致とし、任意Origin、`null` Origin、wildcardを許可しない。
- CORSを無効にし、Host allowlistでDNS rebindingへ対処する。
- CSPを設定し、外部scriptとframe埋め込みを禁止する。
- Panestra MCPのcredentialはセッションごとに発行し、別セッションのtool callへ使用できないようにする。
- MCP credentialは対象セッションの終了時に失効させ、ログと永続データへ保存しない。

### 14.3 認証bootstrap

1. デーモン起動時に短時間だけ有効な1回限りのbootstrap tokenを生成する。
2. デーモンがブラウザを開く場合、tokenをURL queryではなくfragmentへ入れる。
3. ブラウザはfragmentを履歴から除去し、bootstrap endpointへ1回だけ送信する。
4. デーモンはbootstrap tokenを失効させ、現在のデーモンだけで有効なbrowser session credentialをresponse bodyで返す。
5. ブラウザはcredentialを同一originの`sessionStorage`へ保存し、以後のHTTPへAuthorization headerとして付与する。
6. WebSocket接続前に、認証済みHTTP endpointから短時間だけ有効な1回限りのWebSocket ticketを取得する。
7. ブラウザはticketをURLへ含めず、WebSocket handshakeのsubprotocol値として送信する。デーモンはHostとOriginも検証し、upgrade成功時にticketを失効させる。
8. bootstrapまたはticket検証に失敗した場合はPTYを作成せず、再認証を要求する。

browser session credentialは同一タブの再読み込みでは維持され、タブを閉じると破棄される。新しいタブまたはブラウザから接続する場合は、ランチャーまたは明示的な`open`操作が新しいbootstrap tokenを発行する。localhostの別ポートへ認証情報を送るcookieは使用しない。

### 14.4 データ保護と資源制限

- SQLite、履歴、設定、ログをOS所有者だけが読める権限で作成する。
- 履歴保存の無効化、保持上限、保持期間、即時削除を設定できる。
- daemon logへターミナル内容、入力、環境変数、tokenを記録しない。
- ブラウザ通知へターミナル本文や秘密情報を含めない。
- 履歴エクスポートは明示操作でだけ実行する。
- HTTP body、WebSocket frame、入力、grapheme、履歴要求、検索結果へ上限を設ける。
- MCP payload、`taskSummary`、`repositoryPath`、`gitBranch`へサイズ上限を設ける。
- `repositoryPath`はcanonicalize後に存在、ディレクトリ種別、アクセス権を再検証する。
- ANSI parser、binary decoder、圧縮展開をfuzz testする。
- 不正データを接続またはセッション単位で隔離する。

## 15. 障害時の動作

| 障害 | 動作 |
|---|---|
| ブラウザ再読み込み | 同じデーモンへ認証し、セッション一覧とFullSnapshotを再取得する |
| WebSocket切断 | PTYを継続し、再接続後に接続状態を再構築する |
| デーモン終了 | 全セッションを終了扱いとし、管理対象のPTYとプロセスグループを終了して、次回起動時に終了状態を確定する |
| PTY異常終了 | 当該セッションだけを終了し、終了理由を通知する |
| 差分キュー超過 | 当該セッションの中間差分を破棄し、chunk化したFullSnapshotへ切り替える |
| 不正なプロトコル | 当該接続を終了し、PTYは継続する |
| エージェントhook設定、初期handshake、event検証の失敗 | `integration_error`を表示し、ターミナルは継続する |
| MCP申告失敗 | AgentStateを変更せず、行動情報を未取得と表示する |
| MCP切断 | 最後の申告をstale表示し、公式hook連携とPTYは継続する |
| 作業リポジトリ検証失敗 | 申告を拒否し、以前の行動情報を現在情報として上書きしない |
| Git取得失敗 | 前回値をstale表示し、ターミナルは継続する |
| WebGPU device lost | rendererを再生成し、表示セッションを再同期する |
| SQLite書き込み失敗 | 永続化を停止して通知し、PTYは可能な限り継続する |
| ディスク容量不足 | 履歴追記を停止して通知し、PTYと入力は可能な限り継続する |

管理対象のプロセスグループから意図的にdetachした子孫プロセスは、この表の終了保証に含めない。

## 16. 非機能要件と可観測性

### 16.1 初期版の性能方針

- 入力遅延、FPS、起動時間、スループット、CPU、メモリの数値目標を完了条件にしない。
- 最大25セッションは表示・管理上限であり、一定出力量を保証する性能SLAではない。
- 負荷試験と計測機構は実装するが、合否を特定の数値閾値だけで判定しない。

### 16.2 安定性

- 1つのPTY異常終了が他セッションを終了させない。
- adapter、Git処理、描画の個別障害がPTYと入力を停止させない。
- WebSocket切断時も、デーモンが動作中ならPTYを継続する。
- 不正なANSIシーケンスでデーモンを停止させない。
- WebGPU device lost後に画面を再同期できる。
- メモリキューとディスク履歴に上限を持たせる。

### 16.3 可観測性

秘密情報を記録せず、次を計測する。

- セッション別のPTY出力量
- セッション別および接続全体のキュー量
- 差分結合、破棄、FullSnapshot生成回数
- Web Workerの適用待ち量
- 入力から描画までの遅延分布
- 描画回数とdirty region量
- CPU、メモリ、GPU、ディスク使用量
- Git処理とadapter処理の時間、失敗、timeout
- MCP申告の受理、拒否、schema version、処理時間。申告本文とパスはmetricsへ記録しない

## 17. テスト方針

### 17.1 エージェント管制

- 対応バージョンのCodex CLIとClaude Codeについて公式イベントのfixtureを用意する。
- 連携準備中、作業中、承認待ち、ユーザー応答待ちを正しく正規化する。
- ユーザー応答待ちを質問、タスクの完了、失敗のいずれとしても推測表示しないことを確認する。
- 画面文字列だけでは`AgentState`が変化しないことを確認する。
- イベント切断、重複、順序逆転、古いイベントを処理する。
- 連携切断時に`integration_error`を表示し、`agentIntegration`を維持することを確認する。
- 未対応バージョンを`agentIntegration`付きで起動できないことを確認する。
- providerが要求するhookのtrust確認を迂回せず、未承認時は状態連携付き起動を完了しないことを確認する。
- 状態連携のないターミナル上でCodex CLIやClaude Codeを手動実行しても、自動的に`agentIntegration`が付かないことを確認する。

### 17.2 行動開始MCP

- 状態連携付きで起動したCodex CLIとClaude Codeへ、対象セッション専用のMCP接続を注入する。
- `schemaVersion: 1`、一文の`taskSummary`、存在する`repositoryPath`を受理する。
- `gitBranch`を省略でき、申告した場合はGitの実測値で上書きしない。
- Git管理下の通常checkoutと追加worktreeについて、個別のworking tree rootとGit状態を取得する。
- Git管理外の作業ディレクトリを受理し、Git情報なしで表示する。
- repository内のサブディレクトリをcanonicalizeし、Git管理下の場合はworking tree rootを解決する。
- 存在しないパス、ファイルパス、アクセス不能なパスを拒否する。
- 新しい申告で`currentActionId`を更新し、以前のActionContextを履歴として保持する。
- MCP toolが呼ばれない行動を許容し、以前のActionContextを現在の行動として流用しない。
- MCP申告失敗後も公式イベント由来の`AgentState`とターミナル操作を継続する。
- Git変更数をエージェント固有の変更量として表示しない。
- 状態連携のないターミナルへMCP接続を自動注入しない。

### 17.3 ターミナル互換性

- ASCII、日本語、全角、結合文字、罫線、Nerd Fonts
- 対象外の絵文字の置換表示
- alternate screen、カーソル、色、文字属性
- IME、コピー、貼り付け、bracketed paste
- mouse reportingと通常選択の切り替え
- 不正、途中終了、過大なANSIシーケンス

### 17.4 ライフサイクルと通信

- 25セッションの作成、一覧、表示、操作、終了
- ブラウザ再読み込みと再接続
- デーモン終了後に管理対象のPTYとプロセスグループが残存しないこと
- 管理対象から意図的にdetachした子孫プロセスを終了保証のテスト対象に含めないこと
- デーモン再起動後に旧PTYへ再接続しないこと
- 最後に確定したactive screen checkpoint、確定済み履歴、終了状態だけを復元すること
- checkpoint書き込み途中の異常終了で、前回確定したcheckpointを破損しないこと
- 1セッションの大量出力と複数セッションの同時出力
- 差分結合、キュー上限、chunk化したFullSnapshotへの切り替え
- snapshot chunk間へ制御、入力、他セッションのmessageを挿入できること
- 世代不一致、辞書不足、不正フレーム
- 制御メッセージが画面差分の後ろで枯渇しないこと

### 17.5 セキュリティとブラウザ

- 不正Origin、Host、token、CORS要求を拒否する。
- 認証なしHTTP APIとWebSocketを拒否する。
- localhostの認証cookieを発行せず、別ポートへのrequestへ認証情報を送信しないことを確認する。
- browser session credentialによる再読み込みと、1回限りのWebSocket ticketによる再接続を確認する。
- 使用済みまたは期限切れのbootstrap tokenとWebSocket ticketを拒否する。
- tokenと秘密情報がログへ出ないことを確認する。
- データファイルの権限を確認する。
- commandとargsがshellとして再解釈されないことを確認する。
- 対応ブラウザでは起動し、必須機能が不足するブラウザではPTYを作成しない。
- device lostを模擬して再同期する。
- DPI、フォント、Canvasサイズ変更後にグリフが破損しないことを確認する。
